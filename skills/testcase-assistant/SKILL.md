# 测试用例执行助手

页面和 APP 由用户亲自操作。Agent 负责准备数据、说明步骤、核验数据库数据和记录结果，不代替用户操作页面。

用例文件为 `<需求目录>/测试用例/<uat|pre>-testcases.md`。需求文档和技术文档在 `<需求目录>/需求文档.md`、`<需求目录>/技术文档.md`，或需求目录下子文件夹中的 `.md` 文件（文件夹名不固定）。执行结果由 [scripts/result.mjs](scripts/result.mjs) 维护，用法见 `node scripts/result.mjs -h`。

## 开场

1. 读需求文档，有技术文档时一并读，按项目规则加载相关系统知识。
2. 用 `status` 查看用例清单和执行进度，不通读整个用例文件。
3. 等用户指定要执行的用例。

## 执行一条用例

1. 用 `show --case <用户给的标题>` 读取该条用例。用户给的标题可能不完整，后续命令的 `--case` 改用 `show` 输出的完整标题。
2. 按前置条件准备数据：结合知识库、数据库和需求文档，优先找现成数据，没有再造数。告诉用户使用的具体数据。用例和需求文档中的订单号等业务数据只是占位说明，除非用户明确指定，否则不直接使用，按前置条件和步骤描述准备当前环境的真实数据。
3. 按步骤告诉用户要做什么、该看到什么，用具体数据替换泛称。
4. 用户操作完成后，按需查询数据库核验预期；页面表现以用户反馈为准，不需要核验时不查。
5. 给出每一步的结论，用户确认后用 `record` 写入。用户没有明确答复、直接开始下一条用例时，上一条视为通过，用 `--step all --result PASSED` 记录。

```bash
node "<testcase-assistant目录>/scripts/result.mjs" record "<用例.md>" \
  --case "<完整用例标题>" --step 1,2 --result PASSED \
  --actual "用户已验证：列表仅展示 SP2026100071"
```

- `--result` 取 `PASSED`、`FAILED`、`BLOCKED`。
- `actual` 写实际表现；来自用户反馈的注明“用户已验证”，Agent 查库核验的写明核验结果，默认通过的写“用户未反馈异常，默认通过”。

## 修改用例

执行中需要修改用例时，按 testcase-generator 的规则改 Markdown：保留已有 `case_id`、`step_id`，新增步骤生成新 UUID。

- 结果按 ID 关联，改名、改内容、调整步骤顺序后仍对应原记录。
- 已记录步骤的预期被修改时，重新 `record` 该步骤。
- 删除用例或步骤后，用 `status --prune` 清理失效结果。
