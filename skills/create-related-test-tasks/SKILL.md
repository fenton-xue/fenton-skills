# 创建测试拆解工作项

## 输入

开始操作前取得以下信息：

- 父工作项链接。
- 原始 `ID 标题`，格式为 `四个字母-5或6位数字 标题`，例如 `ZYCP-150638 【OSJ】批量删除返金`。
- 优先级（可选）。用户未指定时使用 `P3`。

校验 ID 时使用不区分大小写的模式 `^[A-Z]{4}-\d{5,6}`。无法从输入开头唯一分离 ID 与标题时，先询问用户，不要操作页面。

只接受 `P1`、`P2`、`P3`。用户给出其他优先级时，先询问用户。

## Chrome 操作要求

1. 使用 `chrome:control-chrome` 操作用户当前已登录的 Chrome；先完整读取并遵循该技能。
2. 读取 [DOM 快速路径](references/dom-fast-path.md)，在当前浏览器控制会话中初始化其中的只读辅助方法。
3. 复用用户当前已登录的 Chrome 会话，但每次任务固定新建一个专用标签页打开父工作项链接，不认领、不改动用户已有标签页。两个测试阶段复用本次新建的专用标签页。
4. 将定位范围限制在父工作项弹窗或“建任务”弹窗内，优先按可访问名称、角色和可见文本定位控件。
5. 页面刷新后只重新读取当前弹窗并重建定位器，不复用刷新前的元素引用，也不重复读取工作项列表等无关区域。
6. 如果登录失效、没有权限、控件缺失或页面结构与流程明显不符，停止并说明阻塞位置，不要猜测点击。

## DOM 优先与视觉兜底

1. 先用 DOM 快速路径读取弹窗、定位字段、筛选选项和校验结果，不主动截图。
2. 关键节点使用 DOM 指纹检查页面结构。指纹不匹配时，等待页面稳定后重新读取一次 DOM，并重建当前弹窗内的定位器。
3. 第二次读取仍缺少预期弹窗、字段或列表结构时，判定页面 DOM 已发生变化，再进行截图识别或 CUA 操作。
4. 截图用于识别新版布局和控件位置。确认新结构后优先重新建立 DOM 定位；只有控件没有可用语义或 DOM 定位不可行时才使用坐标点击。
5. 不在 DOM 状态未知时沿用旧坐标、旧元素引用或继续提交。

不要用减少校验、模糊文本匹配或猜测点击换取速度。

## 文本输入与下拉筛选

ONES 的受控输入组件可能忽略 `fill()`、`type()` 或 CUA 文本注入。每次输入后立即读取输入元素的实时 `value`，只有值完全一致时才继续。

对由浏览器按键直接表示的文本，优先逐字符使用 `press()`：

```js
await locator.click();
await locator.press('Meta+A');
await locator.press('Backspace');
for (const char of text) await locator.press(char);
```

逐字符 `press()` 仅适用于能由浏览器按键直接表示的英文文本。中文字符不能作为 `press()` 的按键名称。标题或筛选词包含中文时，先尝试受控文本输入并核对 `value`；若页面仍清空输入，不得继续假定输入成功：

- 标题输入失败时停止并说明阻塞，不提交不完整表单。
- 下拉筛选失败且列表为虚拟列表时，使用 [DOM 快速路径](references/dom-fast-path.md) 的 `visibleOptionTitles()` 分页读取当前候选，并用 `exactOptionSelector()` 选择精确业务选项。

## 数据规则

对两个阶段分别生成标题：

- 一轮测试：`<ID>一轮测试<原标题>`
- 二轮测试：`<ID>二轮测试<原标题>`

保留原标题文字和顺序。分离 ID 与原标题后，移除原标题首尾空白，再将 ID、阶段和原标题直接拼接，三者之间不保留空格。例如：

```text
输入：ZYCP-150638【OSJ】批量删除返金
一轮：ZYCP-150638一轮测试【OSJ】批量删除返金
二轮：ZYCP-150638二轮测试【OSJ】批量删除返金
```

优先级与任务复杂度必须成对填写：

| 优先级 | 任务复杂度 |
|---|---|
| P3 | 简单 |
| P2 | 中等 |
| P1 | 复杂 |

首次进入父工作项链接时，从父工作项弹窗“属性”区域读取“所属产品”当前显示的完整值，例如 `在库系统（OSJ）`，并保存为本次任务的 `父工作项所属产品`。后续创建两个测试任务时始终复用这个完整值，不从原标题、中文方括号或其他字段推导所属产品。

- “所属产品”存在且仅有一个非空值时，原样保存页面显示文本。
- “所属产品”为空、存在多个值或无法唯一读取时，停止并询问用户。
- 创建任务时若“所属产品”已预填且与保存值完全一致，保留当前值。
- 未预填或当前值不一致时，打开组合框，在实际候选项中查找与保存值完全一致的选项；仅有一个精确匹配时选择。
- 没有精确匹配或存在多个精确匹配时，停止并列出实际候选项，不使用简称、模糊匹配或猜测结果。

“所属产品”下拉框为虚拟列表时，读取 `aria-controls` 对应列表的当前可见 `title`，按一个视口约 256 px 分页滚动，直至找到与 `父工作项所属产品` 完全一致的唯一选项或遍历完整个列表。

## 执行流程

打开用户提供的父工作项链接，确认页面对应目标工作项。立即在父工作项弹窗“属性”区域读取“所属产品”，按数据规则保存唯一的完整显示值；完成这一步前不要打开“新建关联工作项”。默认严格按 `一轮测试`、`二轮测试` 的顺序各执行一次完整流程；用户只要求某个阶段或要求提交前审查时，以用户指定范围为准。

首次确认父工作项弹窗结构后，按下列固定语义路径执行，不再为每次点击读取整页 DOM。同一页面结构已在本次任务中验证后，可把相邻点击合并为一次连续操作，但每次点击后仍需做能回答下一步问题的最小状态检查。选择关联关系、选择工作项类型、页面刷新或弹窗重建均属于定位器失效边界；跨越边界后必须重新取得当前弹窗和字段定位器。

对当前阶段执行：

1. 在父工作项弹窗中使用 `tab.playwright.getByText('关联内容', { exact: true }).last()` 打开“关联内容”标签。
2. 使用 `tab.playwright.getByRole('button', { name: '新建关联工作项', exact: true })` 点击“新建关联工作项”。
3. 使用 `tab.playwright.getByRole('dialog').last()` 取得最新创建弹窗；打开“选择关联关系”并选择精确选项“需求拆解的任务”。
4. 等待初始表单刷新完成，丢弃刷新前的创建弹窗 locator；重新使用 `tab.playwright.getByRole('dialog').last()` 取得当前弹窗，并重新定位“* 标题”。
5. 将当前阶段生成的完整标题填入“标题”。替换字段原有内容，不要追加到占位内容或旧值后面；读取输入元素实时 `value`，确认与目标标题完全一致。
6. 在同一份刷新后的创建弹窗中重新定位并打开“* 工作项类型”，确认候选中只有一个业务选项“任务”后选择它。如果业务选项不是唯一的“任务”，停止并说明页面异常。
7. 等待 `tab.playwright.getByRole('dialog', { name: '建任务' })` 出现，丢弃此前的弹窗、字段和候选项 locator；重新取得“建任务”弹窗，执行 DOM 指纹检查并定位全部任务字段。再次读取标题输入元素的实时 `value`，确认仍与目标标题完全一致。
8. 将“优先级”设为用户指定值；未指定时确认其为 `P3`。即使页面默认显示 `P3`，也要读取并确认实际值。
9. 按映射填写“任务复杂度”。
10. 打开“任务拆解类型”，由 Agent 定位该组合框 `aria-controls` 对应的选项列表及其虚拟列表滚动容器。将滚动操作明确作用于选项列表：先把列表翻到最底部，再向上翻一个视口；不得对组合框输入框执行 `End` 或 `PageUp`，也不得滚动整个任务表单。使用 `visibleOptionTitles()` 读取当前视口，正常应能看到当前阶段的“一轮测试”或“二轮测试”。看到目标项时使用 `exactOptionSelector()` 选择精确业务选项并确保与标题一致；当前视口未找到时，由 Agent 根据实际列表结构自行继续向上或向下翻找，不询问用户、不猜测选项、不固定沿用旧坐标。
11. 读取“所属产品”当前已选值。若与保存的 `父工作项所属产品` 完全一致则保留；否则打开组合框，读取实际候选项，并使用 `exactOptionSelector()` 选择与保存值完全一致的唯一选项。虚拟列表按数据规则分页查找；不得从标题提取简称、模糊匹配或选择相似名称。
12. 提交前逐项读取并核对：关联关系、标题、工作项类型、优先级、任务复杂度、任务拆解类型、所属产品。
13. 全部一致后点击右下角“确定”。
14. 等待提交完成，确认新建弹窗关闭且页面出现成功反馈或新关联工作项。无法确认是否提交成功时停止检查，不要再次点击“确定”，以免重复创建。
15. 返回父工作项的“关联内容”，开始下一阶段；继续复用首次进入链接时保存的 `父工作项所属产品`，并确认新任务中的所属产品与其完全一致。

用户要求提交前审查时，在第 12 步校验通过后停止：不要点击“确定”，不要开始下一阶段；将当前标签页以 handoff 状态交还用户，并等待用户明确指示。

## 完成条件

仅在页面中确认两个工作项均创建成功后报告完成。最终回复简要列出：

- 两个已创建工作项的完整标题。
- 使用的优先级及对应任务复杂度。
- 选择的所属产品。

如果只完成一个阶段，明确说明已完成项和未完成项的阻塞原因，不要声称全部完成。
