# 把机器人加为表格的「可编辑」协作者

什么时候用：`access`、`inspect`、`fill`、`comments` 返回退出码 3、输出里有 `needs_access: true`，说明机器人在这张表上不能编辑，脚本什么都没写。

机器人没法把自己加进表格，要借用有这张表「可管理」权限的人的身份，也就是用户本人在浏览器里已登录的飞书账号。

## 先看自己能不能做

自己做要同时满足：

1. 你有能操作网页的浏览器工具。
2. 那个浏览器里已登录用户的飞书账号（能打开这张表）。

缺任何一个，直接跳到最后「加不上就请用户手动加」。

**不要事先猜用户有没有「可管理」权限。** 分享面板里看不出来：实测用户在表上只有「可编辑」或只有「可阅读」时，面板里同样有「邀请协作者」输入框。直接试，最后用 `access` 核对结果。

## 步骤

1. 拿机器人的名字：

   ```bash
   python scripts/feishu_sheet.py access --url "<表格链接>"
   ```

   输出里的 `bot_name` 就是下面要搜的名字。
2. 浏览器打开表格链接，等页面右上角出现「分享」按钮。没有这个按钮：多半没登录飞书，或打开的不是表格，放弃。
3. 点「分享」，等 3 到 5 秒，面板里出现「邀请协作者」搜索框（占位文字是「搜索用户、群组、部门、用户组或智能体」）。
4. 点搜索框，输入 `bot_name`，等结果出来。要有一项和 `bot_name` **完全一致**。没有：放弃（可能是应用没加机器人能力、版本没发布、可用范围不含当前用户，或这张表在别的飞书企业）。
5. 点这一项。面板变成「机器人名字 ·【权限下拉，默认可阅读】· 发送通知 · 取消 / 发送」。
6. 点权限下拉，菜单有「可管理 / 可编辑 / 可阅读」，选「**可编辑**」。选完读一下下拉上的字，必须是「可编辑」；不是就是没选上，放弃，不要继续。
7. 取消勾选「发送通知」（默认是勾上的）。取消后底部按钮从「发送」变成「完成」。读一下勾选状态确认已取消，没取消就放弃。
8. 点「完成」。
9. 核对：

   ```bash
   python scripts/feishu_sheet.py access --url "<表格链接>"
   ```

   `bot_can_edit` 为 `true` 才算成功，然后回去继续原来的写入。点了「完成」但还是 `false`，当作没成功，走最后一节。

## 红线

1. 只加机器人这一个。不改「链接分享」，不加别人，不移除或改动别的协作者。
2. 权限只选「可编辑」，不选「可管理」。
3. 不发通知。
4. 中途任何一步不对（没搜到、选不上「可编辑」、取消不了通知），点「取消」退出，不要提交。

## 操作经验（实测）

1. 权限菜单里的选项，要按元素定位去点（例如「文字是可编辑的那个菜单项」），在同一次脚本里按固定坐标去点，实测点不上。每次点完都读回下拉上的字确认。
2. 面板刚打开、搜索结果出现都要等几秒，不要点得太快。
3. ego-browser 的可用示例：[add-bot-ego-browser.js](add-bot-ego-browser.js)。

## 加不上就请用户手动加

原因可能是：没有浏览器工具、浏览器没登录飞书、搜不到机器人、没有「可编辑」选项、点完核对仍没有权限。用大白话告诉用户，一次只讲这件事：

> 这张表还没把「<bot_name>」加进去，我这边加不了（<一句话原因>）。请你按下面做，需要你是这张表的所有者，或者在这张表上有「可管理」权限：
>
> 1. 打开这张表，点右上角「分享」。
> 2. 在「邀请协作者」里搜「<bot_name>」，点它。
> 3. 权限选「可编辑」，把「发送通知」的勾去掉，点「完成」。
> 4. 做完告诉我，我接着写。

用户说做好了，再跑一次 `access`，`bot_can_edit` 为 `true` 才继续。

- 用户在这张表上只有「可编辑」或「可阅读」：请他找表格所有者，或有「可管理」权限的人，照上面加。能不能自己加取决于这张表的设置，没验证过。
- 表格在别的飞书企业里：机器人属于用户自己的企业，大概率加不进去。请用户改用自己企业里的表格，或者用方式一新建一张。
