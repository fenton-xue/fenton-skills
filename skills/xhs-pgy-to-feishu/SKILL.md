# 小红书博主数据 → 飞书表格

采集脚本和写入脚本分开，中间只传 JSON：

1. `scripts/xhs_fetch.py`：博主标识 → 字段 JSON（调 Rnote 蒲公英接口，按次计费）
2. `scripts/xhs_comments.py`：笔记链接 → 评论 JSON（调 Rnote 爬虫接口，按次计费）
3. `scripts/feishu_sheet.py`：JSON → 飞书表格（飞书自建应用的机器人身份，直连开放平台接口）

只依赖 Python 3 标准库。命令都在本 skill 目录下运行，其中的 `python` 指已装好的 Python 3：macOS 上一般是 `python3`，Windows 上一般是 `python` 或 `py -3`，按实际情况替换。

## 不确定就主动问用户

这个 skill 的使用者不一定熟悉 AI 和命令行。**遇到不确定的事，主动问用户，不要猜，不要自己拿主意。** 用户已经说清楚的不用重复问。常见需要问的情况：

- 取哪篇笔记、抓多少条评论、按什么排序（见下）。
- 表格的表头意思拿不准（见「表头怎么对应」）。
- 帖子在表里已经有了，更新还是追加。
- 博主昵称匹配到多个、或匹配不到。
- 不确定用户说的是哪张表格，或新建的表格该分享给谁。
- 脚本被护栏拦下、或报错后，下一步该怎么办。

问的时候用大白话，一次只问一件事，把选项和各自的结果说清楚。不要把命令、参数名丢给用户。

## 开始前

1. 需要这些环境变量：`RNOTE_API_KEY`、`FEISHU_APP_ID`、`FEISHU_APP_SECRET`；新建表格还需要 `FEISHU_SHARE_TO`（用户本人飞书账号的 union_id，新表格会分享给它）。
2. 运行 `python scripts/feishu_sheet.py check`，输出 `"ok": true` 才继续。不通过就告诉用户运行环境没配好（Python、环境变量或飞书应用），停下来，不要往下做。

## 要不要问用户

1. **字段不用问。** 用户说了要哪些就取哪些；没说就用默认 13 个；已有表格则以表头为准。
2. **取哪篇笔记必须问清。** 只要字段里有笔记层字段（发布链接、发布时间、曝光量、阅读量、点赞、收藏、评论、转发、总互动、关注、笔记标题），而用户没有明确说取哪篇，就停下来问，不要自己选。选项：最早一篇、最新一篇、全部、最新 N 篇。默认的 13 个字段含笔记层字段，所以默认情况下也要问。只取博主层字段（昵称、ID、粉丝量、中位数、CPM 等）时不需要问。

## 方式一：新建表格

用户说「查某博主，建个表放进去」。

1. 采集：

   ```bash
   python scripts/xhs_fetch.py --who "游游酱本酱" --fields default --notes first -o rec.json
   ```

   `--notes` 的值来自用户的回答，见下方参数表。
2. 建表并写入：

   ```bash
   python scripts/feishu_sheet.py create --title "小红书博主数据" -i rec.json
   ```

   新表格归应用所有，会按环境变量 `FEISHU_SHARE_TO` 分享给用户本人，没设置就必须带 `--share-to <union_id>`，否则脚本拒绝执行。**分享对象必须是当前用户本人的飞书账号**，不要自己编一个、不要用别人的，也不要从历史记录里随便取：分享的权限是「可管理」，给错人等于把数据交给了别人。拿不准就问用户。
3. 输出里的 `url` 就是新表格链接，交给用户。表头顺序就是 `--fields` 的顺序。

## 方式二：用户给了已有表格

0. 先查机器人对这张表有没有编辑权限：

   ```bash
   python scripts/feishu_sheet.py access --url "<表格链接>"
   ```

   退出码 3 就是没有，按下面「机器人没有编辑权限时」处理，处理好再往下。读表头不需要这个权限，所以 `inspect` 和预览能成功不代表能写入。
1. 读表头，看哪些认得（认不出的按「表头怎么对应」处理）：

   ```bash
   python scripts/feishu_sheet.py inspect --url "https://xxx.feishu.cn/sheets/xxxx"
   ```

   输出里 `fields_csv` 是该表需要的字段，`unmatched_headers` 是程序认不出的表头（需要你判断，见下面「表头怎么对应」；没有对应字段的列保持空白），`note_level` 为 true 表示表里有笔记层字段，需要问用户取哪篇笔记。
2. 只采集表里有表头的字段：

   ```bash
   python scripts/xhs_fetch.py --who "游游酱本酱" --fields "<fields_csv>" --notes first -o rec.json
   ```

   `note_level` 为 false 时不用传 `--notes`，每个博主一行。
3. 写入：

   ```bash
   python scripts/feishu_sheet.py fill --url "<表格链接>" -i rec.json --write
   ```

   写入前不需要再问用户，护栏（见下）已经保证不会改动已有内容。写完把输出里的表格标题、写入位置和行数告诉用户。不加 `--write` 只会预览，不改动表格，需要看计划时可以用。
4. **输出里 `needs_decision` 为 true（退出码 2）**，说明数据里的帖子（发布链接）在这张表里已经有了，脚本没有写任何内容。把 `duplicates` 里的重复项（帖子链接和已有的行号）告诉用户，问：**更新原有数据，还是追加为新行？** 用户选了之后才重跑：

   ```bash
   python scripts/feishu_sheet.py fill --url "<表格链接>" -i rec.json --on-duplicate update --write
   python scripts/feishu_sheet.py fill --url "<表格链接>" -i rec.json --on-duplicate append --write
   ```

   用户没明确选，就不要自己挑。

## 机器人没有编辑权限时（退出码 3）

`access`、`inspect`、`fill`、`comments` 发现机器人在这张表上不能编辑时，输出里有 `needs_access: true` 和 `bot_name`，退出码是 3，什么都没写。机器人没法把自己加进表格，要借用用户在浏览器里登录的飞书身份。**这件事由你来做，不要让用户去做**，做不成才请用户手动：

1. 直接按 [references/add-bot-to-sheet.md](references/add-bot-to-sheet.md) 用浏览器把 `bot_name` 加为这张表的「可编辑」协作者，不用先问用户。需要你有能操作网页的浏览器工具，并且浏览器里已登录用户的飞书。
2. 不要事先判断用户有没有「可管理」权限，分享面板里看不出来。直接试，试完用 `access` 核对。
3. `access` 里 `bot_can_edit` 变成 `true`，就接着做原来的事，并在回复里告诉用户一句：已把「`bot_name`」加为这张表的可编辑协作者。
4. 加不上（没有浏览器工具、浏览器没登录飞书、搜不到机器人、选不了「可编辑」、核对仍是 `false`）：停下来，按 add-bot-to-sheet.md 最后一节的话术请用户手动加。用户在这张表上只有「可编辑」或「可阅读」时，请他找表格所有者或有「可管理」权限的人加。用户说加好了，再跑一次 `access` 确认。
5. 只加机器人，不改「链接分享」、不加别人、不动别的协作者、不发通知、不选「可管理」。
6. 表格在别的飞书企业里，机器人加不进去：告诉用户改用自己企业里的表格，或者用方式一新建。

## 表头怎么对应

表头先由程序按名称和别名表匹配，会忽略空格、大小写、中英文括号的差别，别名见 [references/fields.md](references/fields.md)（如「曝光」「曝光量」都认）。但程序只认别名表里有的说法，别人换个说法就认不出，所以程序认不出的表头会列在 `inspect` 输出的 `unmatched_headers` 里，**这时由你来判断，不要直接放着不写**：

1. 对照输出里的 `available_fields`（可用字段）。意思明确相同、只是换了说法的（如「曝光数据」就是曝光量，「博主名」就是小红书昵称），用 `--map "表头原文=字段名"` 补上，可以重复写多个，然后重新 `inspect`。最后告诉用户你把哪个表头当成了哪个字段。
2. 意思可能不同、拿不准的，问用户，不要猜。例如「互动」可能是互动量也可能是互动率；「CPM」分图文和视频；「类型」在用户的业务里通常指内容方向（旅行、文化等），本 skill 没有这个字段。
3. 没有对应字段的列（如「备注」），保持空白，不要硬凑。
4. 之后 `xhs_fetch.py --fields` 用重新 `inspect` 输出的 `fields_csv`，`fill` 时带上同样的 `--map`：

   ```bash
   python scripts/feishu_sheet.py fill --url "<表格链接>" -i rec.json --map "曝光数据=曝光量" --map "博主名=小红书昵称" --write
   ```

`--map` 只对这一次运行有效，不会修改用户表格里的表头。

## 写入护栏（防止改坏用户的表）

默认情况下，脚本只往整张子表最后一个有内容的行之后的空白区写，保证：

- 不修改、不清空、不删除任何已有单元格，不插入行，也不移动已有内容。脚本里没有删除和清空的调用，也不要自己用别的方式去改表。
- 判断「最后一行」时看所有列，别的列里的内容也算；图片、附件等非文本单元格也算有内容。
- 写入前会再读一遍目标区域，不是全空就中止，不会写一半。
- `fill` 必须加 `--write` 才会写入；一次最多写 100 行（`--max-rows` 可调）。超过上限被拦下时，先问用户，不要自己加大上限。
- 只会往用户已经授权给应用的表格写。只写用户这次给的那张表，不要写用户没提到的表格。

**唯一放行改已有单元格的情况：用户选了「更新」（`--on-duplicate update`）。** 此时脚本只改发布链接重复的那几行，只改本次有数据的单元格（没数据的格不清空，表里手写的其他列也不动）。改之前会重读这几行的发布链接，有一行对不上就整体中止，不会改一半。一篇帖子在表里有多行、或本次数据里有多条时没法一对一更新，脚本会拒绝，这时只能选追加。

## 写入规则

- **判重只看帖子**：用「发布链接」判断这篇帖子表里是不是已经有了。链接里的 `xsec_token` 每次读取都不同，所以比的是链接里的 24 位笔记 ID。同一个博主的不同帖子不算重复。表里没有「发布链接」列（或这次没取发布链接）就无法判重，一律追加。有重复时停下来问用户，见方式二第 4 步；没有重复就在表尾追加新行。
- 评论工作表（见下）不做判重，同一篇笔记抓两次会有两份。
- 按表头名定位列，不依赖顺序；表头别名见 [references/fields.md](references/fields.md)（如「曝光」「曝光量」都认）。
- 数据里有、表头里没有的字段：直接跳过（`ignored_fields_no_header`）。表头里有、数据里没有的：该列留空。表头认不出的列也留空。
- 超出网格行数会在表格最末尾自动加行。
- 链接列写成可点击超链接；ID 按文本写。
- 子表用 `--sheet` 指定名称或 sheet_id，缺省第一个可见子表。`/wiki/` 链接会自动解析成表格 token（未验证，需要应用开通 `wiki:wiki:readonly`）。

## 抓评论，写进「评论」工作表

用户要抓某篇笔记的评论时用。评论只取一级评论，不取回复。**每个环节都要按下面的顺序，不要跳。**

1. 先查这篇笔记一共有多少条评论（约 1 次请求）：

   ```bash
   python scripts/xhs_comments.py --note "<笔记链接或 24 位笔记 ID>" --info
   ```

   把 `total_level1`（一级评论总数）告诉用户。**为 0 就告诉用户没有评论，到此为止。**
2. **问用户两件事**，没说清就不要往下：
   - 要抓多少条。
   - 按什么排序：`hot` 最热（按点赞）还是 `latest` 最新。
3. 抓取：

   ```bash
   python scripts/xhs_comments.py --note "<笔记链接或 24 位笔记 ID>" --count 36 --sort hot -o comments.json
   ```

   条数不严格：每页条数由接口决定（实测 10 到 15 条不等），一页一页翻到达到条数为止，**整页保留**，不为了凑准确的条数丢掉最后一页里多出来的几条，因为这一页的钱已经花了。例如要 36 条，实际会抓到 3 页共 40 条。评论不够就抓到没有为止。输出里的 `fetched` 是实际条数，`api_calls` 是请求次数，告诉用户。
4. 写入：

   ```bash
   python scripts/feishu_sheet.py comments --url "<表格链接>" -i comments.json --write
   ```

   - 写已有表格（`--url`）时会先查机器人权限，退出码 3 按「机器人没有编辑权限时」处理。
   - 表格里已经有「评论」工作表：在末尾追加新的一块，不改已有内容。没有就新建一个，写上表头「帖子链接」「评论」，并调好列宽。
   - 左列是帖子链接，同一篇笔记的所有评论行合并成一个单元格；右列每条评论占一个单元格。有新帖子就继续往下追加，每篇帖子各自一块。
   - 用户没给表格、要新建：`--new-title "标题"` 代替 `--url`，同样会按 `FEISHU_SHARE_TO` 分享给用户本人，这时表格里只有一个「评论」工作表。
   - 已有的「评论」工作表第一行不是「帖子链接 | 评论」时，脚本拒绝写入，不要改成别的工作表去写。
   - 用 `--sheet` 可以换工作表名；一次最多写 200 条（`--max-rows`）。

## 采集参数速查

| 参数 | 含义 |
| --- | --- |
| `--who` | 昵称（须精确匹配）/ 小红书号 / 24 位 userId / 博主主页链接 |
| `--fields` | 字段名或别名，逗号分隔；`default` 为 13 个投放字段 |
| `--notes` | 取哪些笔记，一篇笔记一行：`first` 最早一篇 / `latest` 最新一篇 / `all` 全部 / 正整数=最新 N 篇。含笔记层字段时必须传，没有默认值 |
| `--business` | 中位数与成本口径：`0` 日常笔记（默认）/ `1` 合作笔记 |
| `--date-type` | 中位数范围：`1` 近 30 日（默认）/ `2` 近 90 日 |

字段全表、各字段来源接口和口径说明见 [references/fields.md](references/fields.md)。Rnote 接口按次计费，只取需要的字段，调用次数就少；给 userId 或主页链接可以省掉一次搜索。

## 失败排查

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| `缺少环境变量 ...` | 凭证没配，或设置后终端没重开 | 告诉用户环境没配好；设置环境变量后要新开终端 |
| 退出码 3、`needs_access`，或 `91403 Forbidden` | 机器人不是这张表的协作者（或不是可编辑），写入没有生效，表格没有被改动 | 按「机器人没有编辑权限时」处理：先自己用浏览器加，加不上再请用户手动加，不要换别的办法去写 |
| `99991663` / `99991661` | App ID 或 Secret 不对 | 检查两个环境变量 |
| `1310213` / `99991672` | 应用没开通表格权限，或开通后没发布 | 开发者后台开通 `sheets:spreadsheet` 并发布版本 |
| `create` 提示必须指定分享对象 | 新表格归应用所有，没人能打开 | 加 `--share-to` 或设 `FEISHU_SHARE_TO` |
| `HTTP 402 余额不足` | Rnote 余额用完 | 充值后重试 |
| `HTTP 403 error code 1010` | Cloudflare 拦了 Python 默认 User-Agent | 脚本已带通用 UA，自写请求时要注意 |
| `没有精确匹配 ... 的博主` | 昵称有差异或博主未入驻蒲公英 | 看候选；改用主页链接或 userId |
| `fill` 退出码 2、`needs_decision` | 帖子（发布链接）在表里已有，脚本没写 | 问用户更新还是追加，再加 `--on-duplicate` |
| `没法一对一更新` | 这篇帖子在表里有多行，或本次数据里有多条 | 只能选追加，或先整理表格 |
| `comments` 提示「第一行不是帖子链接 \| 评论」 | 那个工作表不是评论表 | 换一个工作表名，或让它保持为空 |
| `必须同时指定 --count 和 --sort` | 没问清要抓多少条、怎么排序 | 先 `--info`，再问用户 |
| 表头认不出 | 表头不在别名表里 | 看 `unmatched_headers`，按「表头怎么对应」判断后用 `--map`，拿不准问用户；常用说法也可以加进 `scripts/xhs_fields.py` 的别名表 |
